# PostgreSQL 迁移路径

当前版本继续使用 SQLite，原因是它让校园内测可以零运维启动。代码已经提供稳定的数据导出边界，但**尚未宣称 PostgreSQL 运行时兼容**；`server/store.ts` 仍使用同步 SQLite 查询和部分 SQLite 日期函数。

## 什么时候迁移

出现以下任一信号时启动迁移：

- 多台 API 实例需要共享同一份数据；
- 写入锁等待或高峰期 P95 写请求超过目标；
- 需要只读副本、在线迁移、分区或独立分析库；
- 日活和内容量使单机备份窗口不可接受。

## 已完成的迁移准备

- 表均使用稳定的整数主键和显式外键；
- 上传文件已经与数据库分离，帖子只保存 URL；
- `npm run export:data -- <目标文件>` 可导出业务表；
- 会话和验证码不会进入导出文件；
- CI 会验证身份、发布、关注、图片和私信核心链路。

导出包含密码哈希和私信，必须按敏感数据管理。

## 正式迁移步骤

1. 把 `server/store.ts` 拆成异步 Repository 接口，先实现 SQLite adapter 并保持现有测试通过。
2. 增加 PostgreSQL adapter，将 `datetime/julianday/strftime` 改为 PostgreSQL 时间表达式，布尔值和 JSON 字段改用原生类型。
3. 用导出文件进行一次全量导入，并为帖子搜索建立 `GIN`/全文索引。
4. 在预发布环境做双写校验；按表比较行数、外键、点赞计数和最近消息。
5. 短暂停写，执行最后增量同步，将 API 切到 PostgreSQL。
6. 保留 SQLite 只读备份，观察至少一个发布周期后再下线旧路径。

## 达到大型社区规模还需要

PostgreSQL 只是第一步。多实例部署还需要 Redis（会话、限流、热点缓存）、对象存储/CDN（图片）、消息队列（通知与审核）、OpenSearch/Meilisearch（检索）、可观测性、灰度发布和灾备演练。
